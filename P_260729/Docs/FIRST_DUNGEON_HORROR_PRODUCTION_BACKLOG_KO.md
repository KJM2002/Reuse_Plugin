# 첫 번째 공포 던전 — 에셋·시스템 제작 백로그

문서 상태: 초안 1.0  
연결 문서: `FIRST_DUNGEON_HORROR_DESIGN_KO.md`  
원칙: 기존 기능을 우선 재사용하고, 첫 번째 공포 던전의 완주 경험에 필요한 것만 추가한다.

## 1. 현재 자산과 재사용 방안

| 보유 요소 | 현재 위치 | 재사용 방안 | 현재 한계 |
|---|---|---|---|
| 5×5/13×13 방 생성 | `Plugins/JMRoomGrid` | 던전 좌표, 방 연결과 변형 기반 | 방 역할과 긴장 곡선이 데이터로 지정되지 않음 |

| 문 시스템 | `JMDoor` 및 Integration | 시야 차단, 지름길, 은신처 문 | 던전 문 배치 규칙과 적의 문 대응이 없음 |
| 발소리 | `JMFootstep`, `/Game/Sound` | 플레이어 소음과 표면별 분위기 | 현재 적 AI 청각과 연결되지 않음 |
| 점프스케어 | `JMJumpScare`, `/Game/Jumpscare` | 제한된 사건 연출 | 던전 페이싱 규칙과 연결되지 않음 |
| 상호작용 UI | `JMInteraction` | 문, Loot, 은신처, 단말 안내 | 다른 HUD·Objective·Inventory와 시각 규칙이 다름 |
| 프로토타입 HUD | `UJMPrototypeHUDWidget` | 임시 목표와 알림 | 코드 생성 패널이며 던전용 정보 계층과 스타일 부재 |
| Pretendard 폰트 | `/Game/UI/Font` | 모든 한국어 UI 타이포 통일 | 공통 Text Style/Data Asset 부재 |

## 2. 가장 먼저 필요한 시스템

### P0 — 한 판을 성립시키는 시스템

#### 2.1 던전 콘텐츠 레시피와 구역 역할 배치

현재처럼 방 생성 후 아이템과 순찰점을 단순 분산하지 않고, 한 판의 구조를 데이터로 정의한다.

필요 데이터:

- 입구, 출구, 제어실, 생체 폐기실, 보관실, 휴게실, 위험 보관고 역할.
- 구역별 허용 Loot Table, 은신처 수, 적 순찰 가능 여부, 조명 상태.
- 주 경로, 선택 경로, 순환 경로와 출구까지의 최소 거리.
- 런 Seed에 따른 역할 배치 결과와 도달 가능성 검증.

완료 조건:

- 같은 방 메시를 사용해도 구역의 목적이 구분된다.
- 입구에서 출구까지 필수 경로가 항상 존재한다.
- 파밍 갈래와 추격 우회용 순환 경로가 각각 하나 이상 존재한다.

#### 2.2 탈출구 탐색·해제 Flow

첫 버전의 고정 흐름:

`던전 진입 → 출구 단서 발견 → 비상 배터리 확보 → 전력 제어실 작동 → 출구 개방 → 탈출`

필요 기능:

- 출구와 배터리의 위치를 런 시작 시 결정.
- 표지, 조명과 Objective 이벤트를 단계별로 변경.
- 장치 작동 시 큰 소음 이벤트 발생.
- 출구 개방 뒤 즉시 탈출 또는 추가 파밍 선택 유지.

완료 조건:

- 미니맵 없이 시각 단서만으로 출구 계통을 추론할 수 있다.
- 필수 자원이 없어도 원인을 이해할 수 있는 피드백이 나온다.

#### 2.3 적 AI 상태 확장

현재 시야 기반 `순찰/추격/놓침`을 다음으로 확장한다.

- `Patrol`, `Suspicious`, `Investigate`, `Chase`, `Search`, `Return` 상태.
- 플레이어 발소리, 문, Loot 상자와 출구 장치의 Noise Event 수신.
- 마지막 목격 위치와 마지막 소음 위치 기억.
- 추격 종료 후 일정 구역 수색.
- 상태별 이동 속도, 애니메이션, 사운드와 UI 이벤트.

완료 조건:

- 플레이어가 일부러 소음을 내 적을 다른 길로 유인할 수 있다.
- 시야를 끊는 즉시 적이 포기하지 않고 마지막 위치를 수색한다.
- 상태 변화를 화면 아이콘 없이도 소리와 동작으로 구분할 수 있다.

#### 2.4 적과 JMHide 연결

필요 규칙:

- 은신 완료 시 플레이어의 일반 시야·청각 자극을 억제.
- 적이 은신 진입을 목격했는지 기록.
- 목격하지 않은 은신은 추격을 수색으로 전환.
- 목격한 은신은 문 조사 또는 강제 발각 가능.
- 은신 중 적의 거리와 방향을 발소리로 전달.

완료 조건:

- 추격 도중 코너를 돌아 시야를 끊고 은신하면 생존할 수 있다.
- 적 앞에서 대놓고 로커에 들어가는 행동은 항상 안전하지 않다.

#### 2.5 위험도 기반 Loot 배치

필요 데이터:

- Loot 등급: 일반, 의뢰, 진행, 고가.
- Spawn Context: 선반, 상자, 바닥, 시체, 생체 둥지, 잠긴 보관고.
- 구역 위험도와 출구 거리 기반 가중치.
- 한 판 최소 보장 수량과 희귀 Loot 최대 수량.

완료 조건:

- 의뢰에 필요한 최소 수량은 항상 생성된다.
- 고가 Loot는 안전한 주 경로에 생성되지 않는다.
- 막다른 길이 빈 공간으로 끝나지 않는다.

#### 2.6 던전 결과 요약

필요 표시:

- 탈출 성공·실패.
- 획득한 Loot 종류, 수량과 총가치.
- 의뢰 목표 달성 여부.
- 발견했지만 놓친 고가 Loot 수 또는 위험 구역.
- 다음 탐사로 이어지는 한 줄 동기.

결과 화면은 파밍의 성취와 다음 런의 욕심을 만드는 핵심 콘텐츠로 취급한다.

### P1 — 공포 품질을 만드는 시스템

#### 2.7 공포 페이싱 디렉터

무작위 점프스케어가 아니라 런 단계를 관리한다.

- 진입 후 일정 시간은 직접 추격 금지.
- 흔적 → 원거리 소리 → 짧은 시각 노출 → 첫 추격 순서 보장.
- 추격 직후 회복 시간을 제공.
- 출구 작동 시 마지막 압박 구간 활성화.
- 최근 사건과 같은 연출의 연속 발생 방지.

#### 2.8 소음 전파

- 걷기, 달리기, 웅크리기별 소음 반경.
- 금속, 목재, 점액 바닥별 계수.
- 문, 상자, 장치와 던진 물건의 소음 이벤트.
- 디버그 모드에서 소음 반경과 AI 수신 여부 시각화.

#### 2.9 던전 UI 셸

각 플러그인 Widget을 직접 다시 만들기 전에 공통 스타일과 레이어를 정의한다.

- `DungeonHUD`: Objective, 위험 상태, 핵심 Loot 요약.
- `InteractionLayer`: 상호작용과 은신 진입 안내.
- `ModalLayer`: Inventory, 결과 화면, 일시 정지.
- `NotificationLayer`: 획득, 실패 원인과 시스템 메시지.
- 공통 색, 폰트, 여백, 아이콘 크기와 애니메이션 시간.

### P2 — 첫 버전 이후 확장

- Loot 물리 상태와 파손도.
- 회수 핸드의 잡기·당기기·회전.
- 추가 적과 적별 은신처 대응.
- 여러 출구 해제 방식.
- 환경 규칙 카드와 복합 사건.
- 던전 도감, 기록과 비밀 레시피.

첫 던전은 하나의 모듈러 산업·생체 처리시설 키트로 통일한다.

### P0 — 블록아웃을 벗어나기 위한 최소 세트

| 분류 | 필요한 에셋 | 최소 수량 | 비고 |
|---|---|---:|---|
| 구조 | 벽, 바닥, 천장, 코너, 문틀 | 각 2~4 | 13×13 타일 규격 준수 |
| 연결 | 일반문, 셔터, 통풍구, 파이프 통로 | 4종 | 실루엣으로 경로 구분 |
| 대형 랜드마크 | 처리 탱크 또는 생체 반응조 | 1세트 | 열린 처리장의 방향 기준 |

| 생체 Prop | 점액 덩어리, 낭, 둥지, 촉수 잔해 | 4~6종 | 부산물 파밍 맥락 제공 |
| 표식 | 출구, 전력, 검역, 구역 번호 표지 | 8~12장 | 길찾기의 핵심 에셋 |
| 재질 | 도장 금속, 녹, 젖은 바닥, 점액 | 4개 Master/Instance군 | 동일 팔레트 유지 |
| 데칼 | 누수, 오염, 긁힘, 발자국, 경고선 | 10종 내외 | 흔적과 방향 단서 겸용 |

### P1 — 분위기 강화 세트

- 파손된 Prop 변형과 흩어진 파편.
- 천장 케이블, 매달린 비닐막, 체인과 호스.
- 깜빡이는 조명과 비상등 Blueprint.
- 증기, 먼지, 점액 방울, 누수와 벌레 VFX.
- 출구 전력 연결 상태를 보여주는 케이블 Emissive Material.
- 동일 구조를 다르게 보이게 하는 오염·조명 Variant 세트.

### 환경 에셋 제작 규칙

- 모든 큰 Prop은 평상, 파손, 오염 중 필요한 Variant를 사전에 정의한다.
- 파밍 가능한 가구에는 Loot Spawn Socket 위치를 정한다.
- 숨을 수 있는 가구는 일반 Prop과 실루엣을 공유하되 노란 손잡이 등 일관된 사용 단서를 둔다.
- 장식 Prop은 NavMesh, 적 시야와 플레이어 이동 폭을 검증한다.
- Marketplace 에셋을 사용해도 재질 팔레트, 표식과 조명으로 한 세트처럼 보이게 수정한다.

## 5. 필요한 Loot 에셋

### P0

- 스크랩 3개 실루엣 Variant.
- 점액 샘플 용기 1종.
- 점액낭 또는 생체 부산물 2종.
- 비상 배터리 1종과 장착된 상태 Mesh.
- 희귀 기관 표본 1종.
- Loot 상자/보관함 2종: 조용한 소형, 시끄러운 대형.
- 희귀도 공통 표시: 과도한 Outline 대신 재질, 용기 색과 약한 음향 사용.

### P1

- 오염·파손 Variant.
- 조사 전/후 상태 Mesh.
- 컨테이너 내부 배치용 소형 Prop 세트.
- 결과 화면용 2D 아이콘.

## 6. 필요한 오디오 에셋

### P0

- 시설 Ambience 3층: 저주파 기계음, 환풍/배관, 먼 공간 충격음.
- 적 상태별 음향과 방향성 발소리.
- 문, 로커, 침대, Loot 상자와 전력 단말 상호작용음.
- 녹색/주황/붉은 상태에 대응하는 전기·경보 루프.
- Loot 등급별 짧은 획득음 3종.
- 발견, 추격, 수색 종료를 전달하는 짧은 음악 Stinger.

기존 발소리 에셋은 프로토타입에 사용할 수 있지만, 적 발소리와 플레이어 발소리의 음색을 명확히 분리해야 한다.

## 7. 필요한 UI 에셋과 규칙

### P0 공통 UI 키트

- 9-slice 패널 3종: 기본, 경고, 모달.
- 선형 아이콘: 목표, 출구, Loot, 은신, 소음, 발각, 인벤토리.
- 색상·폰트·여백·애니메이션 값을 가진 공통 Style Data Asset.
- 던전 HUD Widget 1개.
- 상호작용 Prompt Skin 1개.
- Objective Tracker Skin 1개.
- Loot 획득 Toast 1개.
- 추격·의심 상태 Indicator 1개.
- 탈출 결과 화면 1개.

### UI 금지 사항

- 플러그인마다 다른 폰트와 색을 그대로 노출하지 않는다.
- 던전 HUD에 화폐·업그레이드·설명문을 항상 표시하지 않는다.
- 공포를 이유로 필수 피드백까지 숨기지 않는다.
- 상호작용 가능 물체마다 서로 다른 키 표기와 문장 형식을 사용하지 않는다.

## 8. 제작 순서

### 마일스톤 A — 공포 던전 Graybox

- 10~14개 활성 구역의 고정 Seed 한 개 제작.
- 입구, 출구, 제어실, 생체실, 휴게실과 위험 보관고 배치.
- 기존 로커·침대와 임시 Loot 배치.
- 출구 단서를 조명과 표식으로 전달.

완료 조건: 적 없이도 플레이어가 5분 안에 출구 구조와 파밍 갈래를 이해한다.

### 마일스톤 B — 은신 추격 Vertical Slice

- 적 상태를 `순찰/조사/추격/수색`까지 확장.
- JMHide와 적 인지 연결.
- 추격 경로에 로커와 양방향 은신처 배치.
- 소리만으로 적의 접근과 이탈을 판단 가능하게 함.

완료 조건: 플레이어가 적을 유인하고 숨어서 추격을 끊는 데 성공한다.

### 마일스톤 C — 파밍과 탈출 연결

- 위험도별 Loot Table 적용.
- 배터리 확보와 출구 해제 Objective Flow 연결.
- 출구 작동 소음으로 마지막 적 반응 발생.
- 탈출 결과 화면 구현.

완료 조건: 안전 탈출과 추가 파밍 중 실제 선택이 발생한다.

### 마일스톤 D — 아트·오디오·UI 통일

- 모듈러 환경 P0 세트 적용.
- 청소 개체 Mesh, AnimBP와 사운드 적용.
- 공통 UI Style과 던전 HUD 적용.
- 조명, 데칼, Ambience와 공포 페이싱 1차 적용.

완료 조건: 임시 회색 블록과 기본 UE Widget이 플레이 중 시선을 깨지 않는다.

### 마일스톤 E — 플레이테스트와 조정

기록할 지표:

- 첫 Loot 획득까지 걸린 시간.
- 첫 적 인지와 첫 추격까지 걸린 시간.
- 은신처 발견률과 추격 탈출 성공률.
- 출구 발견·해제까지 걸린 시간.
- 평균 획득 가치와 선택 구역 방문률.
- 출구 개방 후 추가 파밍을 선택한 비율.
- 길을 잃은 시간과 같은 방 재방문 횟수.

## 9. 바로 시작할 작업 목록

아래 순서가 현재의 실제 다음 작업이다.

1. 고정 Seed로 10~14개 구역 Graybox를 만들고 각 구역에 역할 이름을 부여한다.
2. 기존 `BP_LootBox_Test`, 로커와 침대를 Graybox에 배치해 탐색·은신 동선을 확인한다.
3. 출구 표식, 녹색 전력선과 배터리 위치만으로 탈출구 찾기 플레이테스트를 한다.
4. `AJMPrototypeGeneratedDungeonDirector`의 고정 아이템 분산 방식을 구역 역할 기반 배치로 교체할 설계를 확정한다.
5. `AJMPrototypeMonster`에 조사·수색 상태와 소음 입력을 추가할 명세를 확정한다.
6. 필요한 환경·적 에셋을 P0 목록 기준으로 직접 제작, 구매 또는 임시 대체 중 하나로 분류한다.

새 기능 개발은 이 Graybox에서 실제로 필요한 것이 확인된 순서대로 진행한다. 에셋도 방을 먼저 채우기 위해 모으지 않고, 각 구역 역할과 플레이를 설명하는 데 필요한 것만 확보한다.
